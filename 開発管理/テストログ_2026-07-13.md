## 環境・インストール方法

```bash
cd PathLift/
pip install -e .          # または依存だけ: pip install pyyaml
pathlift run configs/<recipe>.yaml -o out.gpml
```

- 依存は `PyYAML` のみ（`pyproject.toml`）。`pip install -e .` で `pathlift` コマンドが使えるようになる（`console_scripts: pathlift=pathlift.cli:main`）。
- **`compute: true`（BLASTレスキュー）を試す場合は追加で `blastp`（NCBI BLAST+）が必要**。ローカルに無い環境では `routes.compute: true` のrecipeは`blastp`実行時点で失敗する。
- 相対パス（`source_gpml`等）は recipe ファイルのディレクトリ基準で解決される。

### `blastp` のインストール（macOS、2026-07-13時点で採用した方法）

Homebrewは使わず、bioinformatics界隈で標準的な **conda（bioconda channel）** を採用。

```bash
conda create -n pathlift-blast -c bioconda -c conda-forge blast
conda activate pathlift-blast
blastp -version
```

**動作確認済みバージョン：**

```
blastp: 2.16.0+
 Package: blast 2.16.0, build Mar 28 2025 16:33:14
```

（代替案として、NCBI公式配布物を直接展開してPATHに追加する方法も検討したが、condaの方が既存のRBH_plus/DIAMOND/ggsearch36等の環境と揃えやすく、バージョン固定・再現性の観点でも扱いやすいため採用。）

## 2026-07-13 実行ログ #1 — `compute: false`（回帰確認）

### 呼び出しコマンド

```bash
pathlift run configs/test_0713_Ac_550.yaml -o test_0713_Ac_550.lifted.gpml
```

### 出力

```
[!] 迷子遺伝子を 7 件検出しましたが、routes.compute が無効なため自動レスキューはスキップします。
== pathlift run ==
  source     : .../resource/WP550.gpml
  routes     : symbol  policy=augment
  out_ns     : assembly
  GeneProduct: 18
    matched  : 11
    unmapped : 7
  候補gene総数 : 23
  追加ノード   : 12  (展開後 GeneProduct ≒ 30)
```

### 評価

- **ゲーティング修正が意図通り動作**。`cli.py`の`if unmapped_list and not rc.routes.get("compute")`により、`routes.compute=false`のときBLASTレスキューへ入らず、スキップした旨のメッセージが出力された（ネットワークアクセス無し）。
- **回帰なし**：unmapped=7件は、修正前（`routes.compute`を参照せず常時レスキューが発動していたバグ入り実装）で実際に生成された未マップ一覧（`configs/test_auto_curation.yaml`：TPH1・PNMT・COMT・AANAT・MAOA・ASMT・MAOA重複＝7行）と一致。symbolルートによる基本解決のロジック自体に変化は無いことを確認。
- 集計整合性：matched(11) + unmapped(7) = GeneProduct(18)、展開後 18+12(追加ノード) ≒ 30 で一致。

### 既知の問題点・申し送り

- 今回テストしたコード（`pathlift/cli.py`・`pathlift/blast_runner.py`・`pathlift/recipe.py`）はこの時点で**未コミット**（Codexのコミット待ち）。本テストはこの未コミット版に対して実行した。
- `compute: true`側（`test_0713_Ac_550_compute.yaml`）はサンドボックス環境に`blastp`バイナリが無いため未実行。林さん・大石さんの手元環境（BLAST+導入済み）での実行結果を次に追記する。

## 2026-07-13 実行ログ #2 — `compute: true`（BLASTレスキュー検証）

### 呼び出しコマンド

```bash
# conda環境 pathlift-blast (blastp 2.16.0+) の bin を PATH に追加した上で実行
export PATH="$HOME/miniconda3/envs/pathlift-blast/bin:$PATH"
pathlift run configs/test_0713_Ac_550_compute.yaml -o test_0713_Ac_550_compute.lifted.gpml
```

### 出力（抜粋）

```
[!] 迷子遺伝子を 7 件検出。自動レスキューを開始します...
[*] 6 種類の迷子遺伝子について、UniProtサーバーにFASTA配列を問い合わせます...
  -> [取得成功] ASMT reviewed 3件 / TPH1 reviewed 2件 / MAOA reviewed 2件
  -> [取得成功] COMT reviewed 2件 / PNMT reviewed 4件 / AANAT reviewed 2件
[+] 完了: 6 / 6 件の配列を resource/test_0713_Ac_550_compute_unmapped_queries.fa に保存
[*] リモートBLAST検索 (TaxID: 7461)
  -> [NCBI Gene symbol取得失敗] 107994899: HTTP 429
[+] 自動キュレーションファイルを生成しました: configs/test_0713_Ac_550_compute_auto_curation.yaml
[*] キュレーションを適用してGPMLを再生成します...
[+] 自動レスキューによる補完が完了しました。
== pathlift run ==
  routes     : symbol,compute  policy=augment
  GeneProduct: 18
    matched  : 14
    unmapped : 4
  候補gene総数 : 28
  追加ノード   : 14  (展開後 GeneProduct ≒ 32)
```

### 評価

- **BLASTレスキューが正常に機能**。unmapped 7件のうちTPH1（→Trhn/Hn/pleの3パラログに展開）とMAOA（→LOC107999755）がレスキューされ、matched 11→14・unmapped 7→4（PNMT/COMT/AANAT/ASMTは今回もオーソログなしのまま）。
- 修正前（`routes.compute`を無視して常時発動していたバグ入り実装）で生成された`test_copy_auto_curation.yaml`と、レスキュー内容（TPH1→Trhn/Hn/ple、MAOA→LOC107999755、PNMT/COMT/AANAT/ASMT unmapped）が完全に一致。`routes.compute`のon/off配線・`evalue`注入を加えても、BLASTレスキュー自体のロジックは変化していないことを確認。
- 集計整合性：matched(14) + unmapped(4) = 18、候補gene総数28、追加ノード14で展開後18+14=32、いずれも整合。
- 出力GPMLは`GPML/2013a`のwell-formed XMLとして生成され、`configs/test_0713_Ac_550_compute.lifted.gpml`にコピー済み（PathVisioでの目視確認待ち）。

### 既知の問題点

- **NCBI E-utilitiesのレート制限（HTTP 429）が1件発生**：`auto_curation.py`の`ncbi_protein_to_gene_id`は1蛋白あたりesearch→elink間に`time.sleep(0.34)`を挟むのみで、蛋白間（ループ間）の待機が無い。ヒット数が多いと429が発生し、該当エントリの`target_label`（TextLabel用のGene Symbol）が空欄になる（`target`のGene ID自体は取得できているため致命的ではないが、TextLabelが書き換わらないノードが発生しうる）。リトライ/バックオフ、または蛋白間にも待機を入れる改修を検討の余地あり。
- `blastp`はconda環境（`pathlift-blast`）の`bin`をPATHに追加する形で実行。conda環境自体はこのBashツールのシェルからも`source ~/miniconda3/etc/profile.d/conda.sh && conda activate pathlift-blast`で利用可能だった（手元シェル専用ではない）。
